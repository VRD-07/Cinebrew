CineBrew Language Rulebook

CineBrew is a statically-parsed, stack-VM language compiled directly from C++17 to WebAssembly. Read these exact rules before writing code so you never hit unexpected compiler or VM errors.

Core Rule: Variables Hold Integers Only The VM stack and variable table only store 32-bit integers. String literals (like "Hello") only work directly inside POUR "...";. You cannot store strings in variables or add strings with +.

1. Statements, Semicolons & Comments

  • Every statement (TAKE, assignment, POUR, SHOT, standalone call) must end with a semicolon ;.
  • Blocks enclosed in { ... } do not take a trailing semicolon.
  • Single-line comments start with # and run to the end of the line.
basic_output.cb 
# Single-line comment
POUR "Hello, World!";
POUR 42;

2. Variables: TAKE vs Reassignment

  • Declare once using TAKE name = expr;.
  • Reassign an existing variable without TAKE: name = expr;.
  • Using TAKE on a name that was already declared causes a Redeclaration semantic error.
  • Identifiers must start with a letter or underscore (_), followed by letters, digits, or underscores.
variables.cb 
TAKE score = 10;
score = score + 5;   # Valid: reassignment omits TAKE
POUR score;          # Prints 15

3. Control Flow (IF, ELSE, LOOP)

  • Parentheses around conditions are optional (IF x > 0 { ... }).
  • There is no ELSE IF keyword; nest an IF inside ELSE { ... } instead.
  • LOOP condition { ... } repeats while condition evaluates to non-zero.
control_flow.cb 
TAKE count = 1;
LOOP count <= 5 {
    POUR count;
    count = count + 1;
}

4. Functions (SCENE & SHOT)

  • Define functions with SCENE name(arg1, arg2) { ... }.
  • Return a value with SHOT expr; (or SHOT; to return 0).
  • Functions are hoisted across the whole file: you can call a SCENE before its definition.
  • Parameters are passed on the call stack (read-only). For recursion, always use parameters rather than declaring TAKE variables inside the function body.
factorial.cb 
SCENE factorial(n) {
    IF n <= 1 {
        SHOT 1;
    }
    SHOT n * factorial(n - 1);
}

TAKE result = factorial(5);
POUR result;   # Prints 120

Types, Scoping & Compiler Gotchas

Every quirk below comes straight from the CineBrew compiler and VM source code. Knowing these explains why certain valid-looking patterns behave differently.

Why TAKE x = "Light"; POUR x + y; Fails

What happens under the hood:
  1. The VM stack is strictly std::vector<int> and variables are stored in std::unordered_map<std::string, int>.
  2. POUR "Light"; only works because the VM detects a PUSH of a non-integer literal immediately followed by PRINT and prints the raw text directly.
  3. TAKE x = "Light"; emits PUSH Light followed by STORE x. Because STORE is next (not PRINT), the VM calls std::stoi("Light"), fails, prints a warning, and stores 0!
  4. x + y then executes integer ADD on 0 + 0, outputting 0 instead of "Lightcamera".

Scoping Rules (Flat Global Store)

  • Top-level & blocks: There is no block scope. Declaring TAKE i = 0; inside an IF or LOOP registers i in the single global symbol table for the entire file.
  • Functions: Parameters temporarily shadow globals during semantic checks and read from the call frame (LOADARG) at runtime.
  • Caution in recursion: A TAKE variable declared inside a SCENE still writes to the global vars map via STORE, so recursive calls share it. Keep recursive state in parameters!

Whitespace Around Minus (-)

In lexer.cpp, a minus sign immediately followed by a digit (like -5) is scanned as a negative NUMBER token.

  • a - 5 (with space) parses as a MINUS 5.
  • a-5 (no space) scans as IDENTIFIER(a) followed by NUMBER(-5), causing a parse error! Always put spaces around binary operators.

Booleans, Floats & Unfinished Keywords

  • Booleans: Use integers 1 (true) and 0 (false). The keywords true and false currently trigger a non-integer warning in the VM and evaluate to 0.
  • Unary NOT (!): Only != is accepted by the lexer; standalone !x is rejected. Use x == 0 instead.
  • Floats: Only integers are supported. Decimal literals like 3.14 are rejected by the lexer.
  • BREAK; and CONTINUE;: Accepted by the parser, but currently stubbed in codegen.cpp (they generate a fresh label instead of targeting the enclosing loop). Use condition flags in LOOP instead.

Built-in Functions & Shortcuts

All built-ins return an integer and can be called inside any expression.

Function Args Behavior
abs(x) 1 Returns absolute integer value of x.
min(a, b) 2 Returns the smaller of a and b.
max(a, b) 2 Returns the larger of a and b.
random(max) 1 Returns pseudo-random integer in [0, max - 1].
time() 0 Returns current Unix timestamp in seconds.
print(val) 1 Prints integer val to stdout and returns 0.
